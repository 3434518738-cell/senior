# 三种练习入口的统一服务

## 目的

每日一练、题库专项练习和用户上传题目虽然入口不同，但提交作文后的核心工作相同：读取题目、确认 Task 1 事实、检索 Academic 资料、按四项标准评分并生成反馈。因此项目用一个服务统一编排这条链路，避免三个入口出现不同的评分边界或识图规则。

```text
每日一练 ─┐                       （系统已有题目）
题库练习 ─┼→ 统一练习请求 → 题目事实 → 作文评分 → 范文引用与反馈
用户上传 ─┘          ↓
             Task 1 / Task 2 题目照片自动识别题干
             Task 1 额外识别图表 / 流程图 / 地图
                       ↓
             返回识别结果并提示用户核对
```

## 已实现的接口

### `POST /api/v1/task1/inspect`

只做图片识别，不评分。请求包含 Academic Task 1 图片的 Base64 内容，返回 `chart_understanding` 结构：

- 统计图表：类型、系列、类别/年份、数值和 `estimated` 标记；
- 流程图：步骤顺序和后续步骤/分支；
- 地图：地点、方向和改造前后内容。

用户界面应展示这个结果，允许用户修改或确认。

### `POST /api/v1/practice/score`

三个入口共用此提交接口。`mode` 为 `daily`、`question_bank` 或 `upload`。上传模式只需传 `task_type`、`essay` 和题目照片 `question_image_base64`，不需要手动输入题目。每日一练和题库模式从系统会话中读取题目文本。

- Task 2 上传照片后，Qwen 自动转录完整题干，识别出的题目作为评分依据并从 `recognized_question` 返回；
- Task 1 文字题目或已提供的 `chart_context` 可以直接评分；
- Task 1 上传照片后，Qwen 自动转录题干并识别统计图表、流程图或地图；不要求用户先填写 `chart_context`；可用 `question_image_base64` 同时提供整张题目照片，必要时用 `chart_image_base64` 单独提供清晰图表裁剪；
- 如果客户端已提交 `visual_understanding`，仍必须带 `visual_confirmed=true`，服务会使用用户确认后的事实；
- 自动识别或用户确认后的视觉事实会作为评分上下文，评分阶段不会再次把原图交给模型重复识别；
- 自动识别结果会写入 `chart_understanding`，并在报告中提示用户核对。估读值和不确定项不会单独作为确定性扣分依据。

返回统一结构：

- `mode`、`task_type`；
- `recognized_question`：从图片识别的完整题干和不确定文字；
- 四项 Academic 评分、估分、字数边界、任务完成度检查和警告；
- 已确认的 `chart_understanding`；
- 同 Task 的相关范文引用（仅用于改进参考，不作为分数依据）。

## 设计边界

统一服务不是模型训练，也不是用户账户或题库数据库。每日题目选择、历史记录、用户保存、图片存储和 React 页面仍是后续工作。当前接口先验证后端闭环和输入边界，前端可以在此基础上接入三个入口。

## 关键安全边界

图片识别结果可以直接进入一次评分闭环，因为图片是用户的原始题目输入；题干识别通过 `recognized_question` 返回，报告会明确提示核对识别内容。Task 1 报告还返回视觉结构，并标记“Qwen 自动识别”；含 `estimated` 或不确定项的事实不能单独作为确定性扣分。所有评分仍固定为 IELTS Academic，范文检索不会替代官方评分标准。
