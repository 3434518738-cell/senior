# 流程图与地图识图扩展验收报告

## 本阶段实现

Task 1 图片识别在原有统计图表之外增加两种结构：

- **流程图**：识别步骤文本、顺序和每个步骤指向的后续步骤，可表示分支。
- **地图**：识别位置、方向提示、改造前后状态和变化类别。

识别先进行结构判断，再按对应视觉类型输出结果，避免把地图区域当成图表系列、把流程步骤当成数值点。结果仍放在兼容原报告的 `chart_understanding` 字段内，使用 `visual_type` 区分 `chart`、`process` 和 `map`。

Task Achievement 提示会根据视觉类型切换核对重点：流程图检查主要步骤、顺序和分支；地图检查空间概览、位置及改造前后状态；两类都不会被要求报告不存在的数值或趋势。未确认或不确定图像事实仍需要谨慎处理。

## 控制集结果

本地 `qwen3.5:latest` 使用 GPU 对 6 张项目合成样本逐张识别：

| 指标 | 结果 |
|---|---:|
| 图像类别（流程图/地图） | 6/6 |
| 流程图节点文本 | 14/15（93.3%） |
| 流程图整图顺序正确 | 2/3（66.7%） |
| 流程图箭头关系 | 12/12（100%） |
| 地图发生变化的位置及内容 | 9/9（100%） |
| 地图变化的 before/after 字段 | 18/18（100%） |

分支流程图中，模型保留了所有箭头关系，但遗漏一个分支终点的框内标签，因此不能只看边关系分数。后续应优先提升流程节点召回率和复杂版式鲁棒性。

## 结果边界

这 6 张都是项目内生成的、文字清晰的合成控制图，不是 IELTS 官方公开样题，也不是考场真题。结果不代表真实考试图片的识别准确率，也不代表作文评分准确率。公开样题或出版物题目取得授权并完成来源核验后，应另建真实样题测试集，单独报告结果。

真实图片自动评分前，用户应能检查模型读出的题目事实。错误、模糊或未经确认的读图信息不应直接作为 Task Achievement 的确定错误依据。当前项目已有评分 API，但尚未实现前端的读图确认交互。
