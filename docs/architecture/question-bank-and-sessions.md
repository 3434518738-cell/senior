# Academic 题库与练习会话

## 数据来源

题库从 `data/corpus_staging/task1` 和 `task2` 读取已经通过 Academic 校验的语料。缺少必要字段、标记为不适合检索的源文记录不会进入题库。当前同步数量为 36 篇可用 Task 1 和 28 篇可用 Task 2；范文的题目、题型、图表类型、主题和来源页码会写入 SQLite。

SQLite 数据库为 `data/practice.sqlite3`，包含：

- `questions`：Academic 题目和筛选元数据；
- `practice_sessions`：每日或专项练习会话、计时字段和状态；
- `session_items`：会话中的题目、作文、提交时间和 JSON 评分报告。

数据库在应用启动时自动创建，并用当前经过校验的语料执行幂等同步。数据库和本地语料都在 `.gitignore` 中，不会上传到 GitHub。

## 每日一练

创建 `mode=daily` 会话时，系统随机选择一篇 Task 1 和一篇 Task 2，并默认提供 3600 秒计时。每个每日会话最多刷新 3 次；刷新会替换这一对题目并重置计时，提交任意一篇作文后不能再刷新。

## 专项练习

创建 `mode=question_bank` 会话时必须传入 `task_type` 和 `question_id`。服务会核对题目确实属于对应的 Academic Task，然后创建单题会话。提交时，服务从会话取回原题，避免客户端篡改题目文本后再评分。

## 提交与评分

会话提交复用统一练习服务：Task 1 可以直接上传题目照片，服务自动调用本地 Qwen 识别图表、流程图或地图，再按官方 Academic 四项标准评分；识别结果和“建议核对”警告会随评分报告保存。若客户端已经提供并确认 `visual_understanding`，服务会直接使用确认后的事实。每日会话的两篇作文可以分别提交；全部项目提交后会话状态变为 `submitted`。

当前语料题库中的 Task 1 记录主要保存题干、题型和范文，原始图像/完整图表数据尚未全部入库。因此没有随题库保存原图时，客户端需要在提交时上传题目照片，或提供 `chart_context` / 已确认的 `visual_understanding`；三者都缺少时，服务会拒绝评分，避免凭空判断数据准确性。补齐题库图片是后续任务。

当前前端已经提供每日一练倒计时和刷新按钮；超时后的页面提交会被锁定。后端尚未把超时写入独立状态，也没有草稿自动保存、用户账户和历史趋势页面，这些属于下一阶段产品功能。
